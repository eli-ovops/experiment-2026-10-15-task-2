常规必需镜头合计30秒。若插入S10，各段后续时间码顺延，以最终EDL为准；时长不是成功承诺。真实失败可能使S6、S7素材不存在，届时交付实测失败版并明确缺口，不能制作虚构网页。制作单要求的版本号、完整回答、电脑HTML截图另存证据，不受30秒粗剪节奏限制。

## 原始录屏与计时约束

1. 开测前先做可播放录屏验证；确认真实录制权限与文件生成成功后开始正式全程录屏。
2. 对齐屏幕录制起点与UTC/北京时间时钟；T0为本轮右键选择WorkBuddy时，T1为首问真实完成，T2为第二问真实完成。第一问耗时按制作单T1−T0计算，不能暗改成按发送时刻。若另记发送时刻，作为辅助指标明确命名。
3. 原两句不改字。日期歧义先截图记录，追加澄清单独编号；保留原始两轮，不覆盖重测。
4. 手机预览需使用WorkBuddy真实输出HTML，不自己生成替代。原HTML保留字节原件；若需网络资源，记录实际加载结果。
5. 左上/右下角及任务栏可能含账号信息，粗剪可定向遮挡非必要身份；保留未经剪裁原件的访问边界，不在对话复制账号秘密。

## 可执行剪辑方式

现有 ffmpeg 6.0 实测支持crop/scale/pad/setpts/fps/vstack/hstack/drawbox/drawtext及libx264。已完成0.5秒1920×1080灰色校准输入→裁切→1080×1920 H.264 null输出（返回0），未生成视频文件，非WorkBuddy素材。见tool-capability.json。

对真实录屏逐段填写shot-log-template.csv后，裁切坐标必须根据实际帧截图决定，不能套示例坐标裁掉文件名/数字。最终输出建议命名WorkBuddy_实测_无配音粗剪_1080x1920_v1.mp4；实际制作时用`-n`防覆盖。无音轨用`-an`，封装用`-movflags +faststart`。若以 ffmpeg 完成粗剪，无需为此安装新框架。

## 最终文件验证

- 元数据：1080×1920、SAR 1:1、H.264、yuv420p、无音轨；读取实际时长、帧率、字节大小与SHA256。
- 完整解码：`ffmpeg -v error -i 成片.mp4 -f null -`须无解码报错；原始录屏也做同样检查。
- 可播放：在现成播放器实际打开成片，检查开头、中段、结尾及关键转场；元数据和完整解码不替代肉眼查看。
- 真实内容：逐镜头比对原屏幕录制，不裁掉错误/澄清；截图里的字必须人工查看，不靠DOM或数字脚本声称已看见。
- 数字：对话和HTML分别核制作单三项及其余区域；若不一致，粗剪保留实际结果，结果模板写明错误。
- PATH 的ffprobe架构不兼容；已有Remotion ffprobe n7.1使用其所在目录为cwd时可运行，能查媒体元数据。入口：`/Volumes/EXTERNAL/自媒体/motion-sample-20261012/v3-remotion/node_modules/@remotion/compositor-darwin-arm64/ffprobe`。媒体输入须用绝对路径。无需安装Rosetta或其他工具。
